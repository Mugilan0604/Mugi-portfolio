BUG-204 Severity: High Priority: P1

Checkout submit button remains disabled when entering valid 10-digit postal code with trailing whitespace

Project / Module:E-Commerce Checkout • Billing Service
Environment:Chrome 124 / Windows 11 / Staging Build v2.4.1
Test Type:Functional • Boundary Value Analysis (BVA)
Status:Verified & Closed

Steps to Reproduce:

  1. Navigate to /checkout as an authenticated customer.
  2. Add items to cart with total value exceeding minimum order amount ($50.00).
  3. Fill in customer name, street address, and city correctly.
  4. Enter postal code as "600001 " (6 digits followed by one trailing space character).
  5. Click outside the field or press Tab to trigger blur validation.
  6. Observe button #btn-place-order.
Expected Result:

Application trims string whitespace on input. Postal code is parsed as valid "600001", validation passes, and the "Place Order" button enables.

Actual Result:

Strict regex rejects whitespace as non-numeric characters. Place order button remains permanently disabled with no user-facing error message.

Console Log & API Response:

POST /api/v1/checkout/validate-address
Status: 422 Unprocessable Entity
Response: { "field": "postal_code", "error": "Regex mismatch: ^[0-9]{6}$" }
